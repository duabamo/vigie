      Règles de détection

      Seuils du projet · montants en dirhams
      RÈGLE 01Élevée

      Montant élevé

      Une alerte dès qu’une transaction dépasse le seuil défini.

      > 10 000 DH
      Seuil strict : 10 000 DH ne déclenche pas d’alerte.
      RÈGLE 02Critique

      Déplacement impossible

      Deux transactions d’un même client dans des villes trop éloignées.

      > 900 km/h
      Intervalle ≤ 2 min · distance ≥ 50 km · formule de Haversine.
      RÈGLE 03Modérée

      Fréquence inhabituelle

      Plusieurs transactions du même client dans une fenêtre temporelle.

      ≥ 3 transactions
      Fenêtres fixes de 2 min, calculées en temps événement.

      Démonstration
      Garanties de traitement et limites

      Temps événement. Spark utilise l’horodatage de la transaction et un watermark de 10 minutes pour borner son état. Les fenêtres de fréquence sont actualisées dès le troisième événement ; leur compteur peut évoluer jusqu’à la clôture par le watermark.

      Reprise. Chaque requête possède son checkpoint. Les alertes reçoivent un identifiant déterministe ; les écritures Cassandra sont des upserts. La publication Kafka peut être rejouée : les consommateurs doivent appliquer les mises à jour par alert_id.

      Supervision. Une connexion TCP réussie indique un port joignable. Elle ne prouve pas le bon fonctionnement de toute la chaîne. Les erreurs Cassandra sont affichées sans remplacement par des données simulées.

      Géographie. Le référentiel contient huit villes marocaines. Une ville inconnue ou un message invalide est envoyé dans le topic de rejet.

      Lire les indicateurs

      Choisissez une période en haut de page. Tous les indicateurs, graphiques et listes suivent cette période. Les montants sont exprimés en DH et les heures sont affichées dans le fuseau Africa/Casablanca.

      Une transaction peut déclencher plusieurs règles. Le taux de transactions signalées compte chaque transaction une seule fois.

      Suivre une alerte

      Dans « Alertes », recherchez un client ou filtrez par règle et niveau. Ouvrez une ligne pour lire les motifs et les données de la transaction.

      Faites passer l’alerte en cours d’analyse, puis confirmez-la ou écartez-la. Le suivi est conservé localement et persiste après un redémarrage.

      Vérifier les détections

      L’« Atelier de démo » permet de faire varier quatre cas : montant, déplacement, fréquence ou paiement habituel. Chaque essai affiche les transactions et les alertes produites.

      Vous pouvez mettre le flux en pause ou changer sa cadence. Les essais manuels restent disponibles pendant la pause.

      Conserver les résultats

      Le bouton « Exporter » produit un CSV compatible avec les tableurs. Depuis les alertes ou les transactions, il reprend la recherche et les filtres actifs, sur toutes les pages.

      Les données de démonstration sont identifiées dans le fichier exporté.
